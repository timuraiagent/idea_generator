  `# >>> kb secrets` и `# <<< kb secrets` — этот блок руками не правь. Нужен новый ключ — попроси пользователя
  добавить его в kb (вкладка «Секреты») и выдать проекту. Запуск с секретами без `.env`: `kb run -p idea_generator -- <команда>`.

- Коммить небольшими осмысленными шагами.
- Push — только когда пользователь просит.
- Дела, списки и контакты пользователя — через скиллы kb (`kb-todo`, `kb-lists`, `kb-contacts`), не локальными файлами.

## Как устроен код

- `scripts/sample_pairs.py` — сэмплирование далёких пар «глагол × существительное» из word2vec.
  Модель: RusVectores `ruwikiruscorpora_upos_cbow_300_20_2019` (лежит в `.data/nlpl_model/model.txt`,
  в git не входит — скачать: `curl -o .data/nlpl_model/180.zip http://vectors.nlpl.eu/repository/20/180.zip && unzip`).
  Запуск: `python3 scripts/sample_pairs.py .data/nlpl_model/model.txt --mode random --threshold 0.15 --n 60`
  Режимы: `random` (случайные пары с sim < threshold), `far` (для глагола — дальнее существительное),
  `--seeds <файл>` (для заданных слов найти дальних партнёров). Косинусная близость < 0.15 = «достаточное
  расстояние»: понятия не смежные и не из одного контекста, но оба живые и частотные. Результаты — в `.data/out/`.

## Пайплайн: от пары понятий до прототипа механики

Четыре роли, у каждой свой исполнитель; артефакты живут в репозитории:

1. **Сэмплер** — `scripts/sample_pairs.py`: пары «глагол × существительное» на достаточном расстоянии
   (режим `random --threshold 0.15` или `--seeds`). Эскиз механики из пары пишет ведущий.
2. **Фильтр** — свежий субагент *без* контекста поиска: сам проверяет эскиз по чеклисту
   (это механика, а не тема; новизна — независимая веб-проверка; есть решения и петли;
   прототипируемость одним HTML-файлом) **+ гейт глубины** (можно ли строить уровни и
   усложнять: ≥2 оси рекомбинации; дерево навыков из ядра с глубиной, а не широтой;
   замок/ключ вырастают из самой механики, лучше — динамический замок «ключ производится
   и тратится»; определён тип прогресса — задачи/расстояние/персонаж/игрок; комбинации
   враг×условие ломают доминирующую стратегию; уровни = по одной новой идее, вводный
   уровень безопасен, на каждый навык ≥2 уровня с разными решениями). Вердикт go/no-go +
   доработанная спека → `mechanics/<slug>/spec.md`.
3. **Визреференс (Codex)** — по спеке делает `mechanics/<slug>/reference.html`
   (HTML-сторибоард: сетка SVG-кадров состояний механики) и лист ассетов
   `prototypes/<slug>/assets.svg` (сетка 128×128, координаты каждого спрайта задокументированы в комментарии).
4. **Сборщик прототипа (Claude)** — одиночный `prototypes/<slug>/index.html`
   (canvas + спрайты из assets.svg): один экран, одна проверяемая гипотеза
   («один прототип — один вопрос», вопрос — в заголовке страницы).
   В конце пересобрать дашборд (`python3 scripts/build_dashboard.py` — карточки всех
   прошедших фильтр механик со ссылками игра/референс/спека), держать сервер из корня репо
   (`python3 -m http.server 8788`) и дать пользователю адрес вида `http://<lan-ip>:8788/`,
   чтобы играть с ноутбука. Затем `git push origin main` — GitHub Pages
   (https://timuraiagent.github.io/idea_generator/, дашборд в корне репо, ссылки относительные)
   обновится и станет доступен тестерам.

Запуск: названа механика → шаги 2–4 (шаг 1 уже сделан сэмплером).
