# Излитое — спецификация v1 (после фильтра, GO* 16/16)

## Название
Излитое (рабочее; слот pour-algorithm).

## Пара-источник
изливать_VERB × алгоритм_NOUN (этап 1 — Σ8, потолок пары 16: №1 = 2, №4 = 2 — мост
«лить код», «залить на прод», №5 = 2 — рукой льёшь, исполняется само и больше человека,
№8 = 2 — перенос). Стоп-лист чист. Формула пары: **можно изливать алгоритм, но тогда он
потечёт сам: излитое начинает исполняться и льётся по шагам, пока не разольётся до конца**.

## Правки фильтра (шесть, закрывают №10 и №14 одной геометрией)
1. **Лист — один экземпляр (№9/№10).** Эскиз говорил «теряет носителя», но не запрещал
   излить тот же алгоритм снова. Правка: излитый лист уходит из книги навсегда —
   повторный излив невозможен; «КОТОРЫЙ лист» становится невозвратным выбором.
2. **«Непредсказуемо» → детерминированный жёлоб (№11; урок «Льётся»/«Крахмала»).**
   Эскизное «растекается новыми шагами непредсказуемо» заменено дискретным законом:
   шаг падает там, где стоит голова; после шага голова прыгает по ТЕКУЩЕМУ жёлобу зоны;
   поворот между тиками меняет следующий прыжок; исполненные шаги не вернуть. Уровень
   решается на бумаге и перебором — непрерывна только струя-анимация.
3. **«Остановить нельзя» × «стоп-русло» сняты Сливом (№15).** Паузы и отмены нет, кнопка
   сдачи активна лишь когда всё излитое разлилось или утонуло; «стоп» = подставить
   колодец: голова, прыгнувшая в слив, топит остаток листа ЦЕЛИКОМ. Цена честная —
   утопленные шаги не работают на задачи.
4. **Проходы (№12/№15).** Узлы двора (перекрёстки), куда изливать НЕЛЬЗЯ — в них только
   подставляют жёлоб; шаг, исполненный в проходе, грохается на пол. Геометрия становится
   делом: через проходы прокладывают маршруты, но не решают там задачи.
5. **Двусторонний спрос конкретизирован (№10).** Ручного исполнения шагов у игрока нет
   вовсе — задачи закрываются только излитым (хочется излить больше); при этом у листа
   бывает вредный хвост, а лист один (иногда правильно НЕ изливать оставшийся лист).
6. **Цель и par (№14).** Эскизное «провести 4 алгоритма за партию» заменено партией из
   5 дворов; звёзды за повороты жёлобов ≤ par; par и пороги ботов подтверждены перебором
   и рандом-ботом на скелете до HTML (см. «Критерии приёмки»).

## Правило (одно предложение)
Оторвать лист от книги — значит ИЗЛИТЬ его: первый шаг падает там, где ты излил, голова
сразу прыгает по жёлобу этой зоны, и дальше лист льётся сам — шаг за шагом, строго по
своему порядку, каждый тик один шаг падает там, где стоит голова, и голова уходит по
жёлобу; паузы нет, отмены нет, излитый лист из книги уходит навсегда, голова, прыгнувшая
в слив, топит остаток листа целиком, а в проходе шаг грохается на пол; рукою ни один шаг
не исполнить — тебе принадлежат только жёлоба: который лист излить, куда его излить и
какой жёлоб в какой момент повернуть, чтобы каждый шаг упал в своё дело и ни один не
разбил хрупкое.

## Глаголы игрока
- **Излить** (клик по листу в книге → клик по дворовой зоне): первый шаг падает в зоне
  излива немедленно, голова прыгает по её жёлобу, тик-час завёлся. В проход изливать
  нельзя (клик отклоняется); в слив можно — лист тонет целиком, ни одного шага.
- **Повернуть** (клик по зоне без листа в руке): жёлоб зоны переходит к следующему
  соседу по кругу; тратит один жёлоб из запаса уровня. Поворот, сделанный до тика,
  забирает голову ПОСЛЕ шага этого тика.
- **Сдать двор** (кнопка): активна, только когда все излитые листы дошли до конца
  (исполнены или утонули). Проверка задач и хрупкостей.
- **Заново** (кнопка R): двор сбрасывается целиком.
- Единственный глагол — КЛИК; аватара и ходьбы нет. До первого излива время не идёт.

## Токены
- **Книга листов** (1–4 на двор): лист = упорядоченная лента шагов-иконок (2–3). Один
  экземпляр; излитый лист покидает книгу навсегда.
- **Шаги (3 типа)**: ВОДА (ведро), ЩЁТКА, ТОПОР. Иконки на ленте листа и в задачах.
- **Зоны двора** (2–8): задача-рамка («тип × N» — вода на грядку, щётка по кляксе, топор
  по завалу), хрупкость (перечёркнутый тип: топор в витрину/грядку нельзя), ПРОХОД
  (арка: излива нет, шаги грохаются на пол), СЛИВ (колодец: голова, прыгнувшая в него,
  топит остаток листа).
- **Жёлоб**: стрелка зоны на соседа (по кругу соседей). Начальные жёлоба заданы двором;
  запас поворотов = par+2 (жёлоба кончились — клики отклоняются).
- **HUD одной строкой**: «двор i/5 · задачи X/Y · поворотов: Z (par P)»; кнопки «Сдать
  двор», R; лента каждого текущего потока с отметкой исполняемого шага.

## Инвариант и математика v1 (детерминированная, №9)
- **Порядок — закон**: шаги листа исполняются строго по порядку; каждый шаг исполняется
  ровно один раз — ни пропустить, ни повторить, ни остановить; лист кончается исполнением
  или утоплением остатка целиком (шаги не дублируются и не исчезают по одному).
- **Излитое не возвращается**: лист излит — из книги ушёл навсегда.
- **Голова честная**: прыжок головы всегда по текущему жёлобу зоны, где шаг только что
  исполнился; поворот влияет лишь на следующий прыжок; в слив — тонет с остатком.
- **Резолв тика** — чистая функция `(граф двора, жёлоба, потоки)`: потоки исполняются по
  порядку излива; счётчики задач монотонны; хрупкость разбита навсегда, если шаг этого
  типа упал в зону хоть раз.
- Следствие для солвера: состояние двора — чистая функция последовательности кликов;
  перебор конечен и мал (дворы ≤ 8 зон, листы ≤ 4, повороты ≤ 5) — par доказуемо полным
  перебором при сборке.

## Петли
- **P1 излил → течёт сам**: клик только запускает; дальше тик-час сам (1.5 с/шаг), паузы
  нет — решение «который лист и куда» живёт в момент излива, исполнение — без тебя.
  +/конструктивное/низкое/немедленная/узкая/двор/короткая.
- **P2 жёлоб решает заранее**: поворот до тика — куда уйдёт голова после шага; чтение
  графа на 1–2 прыжка вперёд = главная арифметика (L2–L5). +/конструктивное/высокое/
  отложенная/широкая/двор/средняя.
- **P3 хвост и колодец**: полезная голова листа тащит вредный хвост — увести в слив или
  погасить в проходе; та же щётка — по кляксе, а тот же топор — по витрине (L3–L5).
  −/destructive/высокое/отложенная/широкая/двор/средняя.
- **N1 лист один**: не излить оставшийся лист — тоже ход; хвост дороже головы (L4/L5).
  −/destructive/среднее/немедленная/узкая/двор/короткая.
- **Против доминирующих стратегий** (боты обязаны подтвердить, см. приёмку): «не изливать
  ничего» — задачи голы, двор провален; «всё в слив» — то же; «всё в первую задачу» —
  хрупкости биты (L4/L5 провал, спам-бот); «крутить жёлоба без разбора» — запас par+2,
  слепое вращение задач не закрывает и звёзды сжигает.

## Цель и проигрыш
- **Партия**: 5 дворов. Цель — сдать все 5 (все задачи закрыты, хрупкости целы).
- **Звёзды за двор**: 3 — сдано и поворотов ≤ par; 2 — сдано и поворотов ≤ par+1; 1 —
  сдано. par — минимальное число поворотов (подтверждается перебор-ботом при сборке).
- **Проигрыша смертью нет**: сдал с негорящими задачами или битой хрупкостью → «двор не
  сходится», R. Двор короткий (1–2 минуты), рестарт только двора.

## Вопрос прототипа (один)
Рождает ли неостановимое самоисполнение + подстановка жёлобов настоящее ЧТЕНИЕ геометрии
двора — какой лист, в какую зону, какой жёлоб в какой момент — или игрок льёт всё подряд
и крутит наугад? Прототип обязан содержать: вредный хвост листа, слив-колодец, проход,
задачу «вода × 2» (мячик в тупик) и спам-бота, обязанного валить L4/L5, — иначе вопрос
решён заранее в пользу «темы».

## Уровни (5, обучение одним намёком; par проверяет перебор-бот при сборке)
Формат: зона(жёлоб→; свойства). Листы: В вода, Щ щётка, Т топор. Бюджет поворотов =
par+2 на двор. Подсветка-призрак первого прыжка — только L1–L2 (намёк-обучение).

- **L1 «Первый лист»** — A(→B), B(→A). Лист л1=[В,В]. Задачи: «вода×1 в A», «вода×1 в B».
  **par 0**. Решение: л1 в A (вода в A; голова в B; вода в B). Учит: клик по листу +
  клик по зоне = излив; шаги идут сами; излитый лист ушёл. Жадный/рандом проходят
  (осознанные брешеры первого двора: излив в B тоже закрывает обе задачи).
- **L2 «Заранее»** — A(→B), B(→A,D,C; жёлоб→A), C(→B), D(→B). Лист л1=[В,В,В]. Задача:
  «вода×2 в D». **par 1**. Решение: л1 в D (вода×1 в D; голова в B); повернуть B (→D);
  тик (вода в B; голова в D); тик (вода×2 в D — мячик D↔B). Учит: жёлоб, повёрнутый до
  тика, забирает голову ПОСЛЕ шага. Ловушки: излив в B без поворота — вода уходит в A;
  поворот «после» — голова уже ушла. Рандом 9.09%.
- **L3 «Хвост»** — A(→B), B(→A,D,S; жёлоб→D), D(→B; хрупкость: топор), S(→B; слив).
  Лист л1=[Т,Т,Т]. Задача: «топор×1 в A». **par 1**. Решение: л1 в A (топор — завал;
  голова в B); повернуть B (→S); тик (топор в B; голова в S — остаток листа утонул).
  Учит: вредный хвост уводят в колодец; окно поворота — между изливом и первым тиком.
  Ловушки: без поворота — третий топор бьёт витрину D (провал); излив в B — второй топор
  в D; поворот после первого тика — поздно (голова уже в D). Рандом 12.25%.
- **L4 «Перекрёсток»** — A(→M; хрупкость: топор), B(→M), M(→B,A,D,E; ПРОХОД),
  D(→M,S), E(→M; хрупкость: топор), S(→D; слив). Листы: л1=[В,В,В], л2=[Т,Т,Т],
  л3=[Щ,Т]. Задачи: «вода×2 в A», «топор×2 в D», «щётка×1 в B». **par 2**. Решение:
  (1) л3 в B (щётка — клякса; хвост-топор грохается в проходе M); (2) л1 в A; повернуть
  M (→A); вода×2 в A мячиком A↔M (средний шаг грохается в проходе); (3) л2 в D; повернуть
  M (→D); топор×2 в D тем же мячиком. Учит: один жёлоб перекрёстка обслуживает все
  потоки по очереди — КОГДА повернуть и КОГДА излить (л2 можно пустить, пока л1 течёт).
  Ловушки: л2 в A — топор бьёт собственную грядку; порядок поворотов перепутан — вода
  уходит в D, топор в A/E. Рандом 0.01% (перекрёсток требует плана; уровень-приём).
- **L5 «Экзамен»** — A(→N; хрупкость: топор), N(→C,A,B; ПРОХОД), B(→N), C(→N,P),
  P(→C,E,D; ПРОХОД), D(→P,S), E(→P; хрупкость: топор), S(→D; слив). Листы: л1=[В,В,В],
  л2=[Т,Т,Т], л3=[Щ,Т], л4=[Щ,Т,В]. Задачи: «вода×2 в A», «щётка×1 в B», «щётка×1 в C»,
  «топор×2 в D». **par 3**. Решение: (1) л1 в A; повернуть N (C→A); вода×2 в A мячиком
  A↔N (средний шаг грохается в проходе); (2) л4 в B (щётка в B; хвост грохается в N,
  вода-огрызок доливает грядку A — не лишняя); (3) л3 в C (щётка в C; топор-хвост грохается
  в N — голова уходит мимо витрин); (4) л2 в D (топор×1; голова в P); повернуть P
  ДВАЖДЫ до тика (C→E→D); тик — топор грохается в P, голова в D; тик — топор×2 в D
  мячиком D↔P. Учит всё сразу: два прохода, делёж двух жёлобов, порядок поворотов.
  Ловушка КОГДА: излить л2 и повернуть P только наполовину (→E) — топор уходит в витрину
  E (провал); без N→A вода×2 в A не набрать (вода уходит в C мимо грядки).
  Рандом 0.01%. Вторая par-форма (перебор): все четыре листа излить вперёд (л1 в A, л2 в D,
  л3 в B, л4 в C), затем N (→A) и P дважды (→D), два тика закрывают грядку и завал.

## Стартовые константы (числа для HTML, править при балансировке)
Один экран 960×640: двор — граф зон (зоны ≥ 96 px, жёлоба — стрелки на рёбрах, числа
«тип × N» в рамках задач), книга листов внизу (ленты шагов крупно), запас поворотов у
HUD. Тик 1500 мс; резолв мгновенный — state() для ботов синхронный; струя — анимация на
ребре (0.4 с). До первого излива время не идёт. HUD одной строкой: «двор i/5 · задачи
X/Y · поворотов: Z (par P)»; кнопки «Сдать двор», R. Все константы в один объект CONFIG;
дворы — данные (zones/dials/leaves/tasks/fragile/sinks/nopour/par/ghost).

## Критерии приёмки (боты)
Экспорт `window.POUR_ALGORITHM` = { CONFIG, LEVELS, loadLevel(n), pour(leafId, zoneId),
rotate(zoneId), submit(), state(), log } — резолв синхронный и детерминированный, полная
информация: задачи, хрупкости, par открыты в LEVELS. Проверено на скелете до HTML
(перебор + Монте-Карло, seed 7): par = {L1: 0, L2: 1, L3: 1, L4: 2, L5: 3} — эталоны
«Уровней» достигают par, решений дешевле par не существует; спам-бот валит L4/L5 (битые
хрупкости); эталон L4 льёт л2, пока течёт л1, и оба жёлоба L4/L5 (M и P) обязаны
побывать в двух положениях (перебор-бот). Любая правка констант — перепрогон перебора
и рандом-модели до сборки.
- **state()** → сериализуемый `{ level, leaves: [{id, steps, used}], flows: [{leafId,
  nextStep, head}], dial: {zoneId: neighborId}, rotationsLeft, counters, broken,
  submitted, over, won, stars }`.
- `pour(leafId, zoneId)` → `{ok, reason}`: 'nopour' (проход), 'used' (лист уже излит),
  'no-leaf' (листа нет), 'locked' (двор сдан). Отказ не меняет состояние.
- `rotate(zoneId)` → `{ok, reason}`: 'empty' (запас кончился), 'locked'. Отказ не меняет
  состояние и не тратит жёлоб.
- **Инварианты (№9) во всех прогонах любых ботов**: шаги каждого потока исполняются
  строго по порядку ленты и ровно один раз; тонущий лист теряет остаток целиком; излитый
  лист не возвращается; голова прыгает по жёлобу на момент прыжка; излив в проход
  невозможен; одинаковые последовательности кликов дают одинаковые состояния; счётчики
  задач монотонны; хрупкость, разбитая хоть раз, разбита навсегда.
- **№13-щит**: подмена «алгоритм → ресурс» ломает закон порядка и самоисполнения (ресурс
  не исполняется сам и не держит порядок шагов); «изливать → использовать» ломает
  неотзывность и неостановимость (использование можно прекратить и оно не течёт по
  жёлобам) — правила меняются.
- **План-бот** (решения из «Уровней» через pour+rotate+submit): все 5 дворов сданы,
  поворотов = par → 3★ везде. Обязательный порог.
- **Пассив-бот** (submit сразу): 0 задач, все дворы провалены. Обязательно (№14 «не
  применять»).
- **Спам-бот «в первую задачу»** (все листы в зону первой задачи, ни одного поворота):
  L1 проходит (осознанный брешер первого двора), L2–L5 — провал: L2 — вода×2 в D не
  набрать, L3 — витрина D разбита хвостом, L4/L5 — хрупкости биты топорами. Обязательно
  (№14 «свалить в центр»).
- **Рандом-бот** (случайное легальное действие, автосдача по исчерпанию; 20 000 прогонов,
  seed 7): **L5 — сдано < 5%** (замер скелета: 0.01%) — обязательный экзаменационный
  порог; L4 — 0.01%: перекрёсток не проходится удачей (уровень-приём, экзамен — L5);
  L2 — 9.09% и L3 — 12.25% — учебные потолки; L1 — 100% (осознанный брешер).
- **Перебор-бот** (все последовательности действий): решений «поворотов < par» не
  существует; на L4/L5 оба жёлоба перекрёстка обязаны побывать в двух положениях.
  Обязательно.
- Любая правка констант — перепрогон всех ботов до сборки.

## Риски баланса
- **«Жёлоба не читаются»**: стрелки на рёбрах + призрак первого прыжка на L1–L2; лента
  листа подсвечивает исполняемый шаг и следующую зону падения. Если игроки промахиваются
  системно — показывать призрак всей цепочки первого листа, не скрывать жёлоба.
- **«Тик давит»**: 1500 мс на шаг — паузы нет, но до первого излива время не идёт; если
  игроки не успевают думать — увеличить тик до 2000 мс, не вводить паузу (пауза ломает
  «остановить нельзя»).
- **«Сдал с негорящей задачей» виден только при сдаче**: рамки задач и хрупкости
  подсвечивать состоянием в реальном времени (свет/крест); сдача — только фиксация.
- **Клерковость** (посчитал и кликнул): давят делёж жёлобов (L4/L5), вредные хвосты и
  par, требующий лить второй лист, пока течёт первый. Если всё равно скучно — добавить
  двор с двумя перекрёстками, не таймер.
- **Мячик в тупик** (вода×2 через bounce) может выглядеть багом («шаг пропал в проходе»):
  шаги в проходе гасить прозрачностью с частицами «на пол»; в ленте листа помечать
  грохнувшиеся шаги.
- **Запас поворотов par+2** — жёсткий: если игроки тупят в «жёлоба кончились» — не
  увеличивать запас, а упростить начальные жёлоба двора (контроль par перебор-ботом).

## Что НЕ входит в v1 (осознанно вырезано)
- **Редактирование листа** (переставлять шаги, дописывать) — порядок листа есть закон
  существительного; редактор ломает №9 и превращает игру в Human Resource Machine.
- **Пауза/отмена потока** — запрещены законом глагола («остановить нельзя»); слив —
  единственная «остановка», и она топит остаток.
- **Свои листы-композиции** (собрать алгоритм из шагов), враждебные потоки NPC, параллель
  с противником, несколько сливов на двор, генерация дворов, таймер-давление сверх тика,
  звук, мобильное, сохранения — v2.
- **Непрерывная физика струи** (скорости, волны, гидравлика) — дискретные тики и жёлоба
  ради бумаги, ботов и повторяемости (урок «Льётся»).

## Родство (проверка фильтра, строгая)
- **«Льётся»** (литься × замещение): там поток МАТЕРИАЛЬНЫЙ — давление гонит содержимое
  зон, вытеснение уходит в никуда, игрок владеет ЗАСОВАМИ (время: открыть/закрыть);
  здесь потока-материала нет вовсе — течёт ИСПОЛНЕНИЕ по чужому порядку шагов, засовов
  нет (остановить нельзя), игрок владеет ЖЁЛОБАМИ (геометрия). Ядро решений: план
  открытий и бюджет материала против чтения графа и дележа жёлобов во времени.
- **«Растечься»** (растекаться × подробность): там несжимаемые единицы и АДРЕС ИСТИНЫ
  первой лужи; здесь единиц нет — шаги одноразовые и выгорают при исполнении, никакой
  истинности, главный вопрос — куда упадёт СЛЕДУЮЩИЙ шаг, а не где правда.
- **«Черпало»** (черпать × завтра): там событие снимают с расписания РУКОЙ (черпак) и
  переносят, отсчёт замирает — остановка возможна; здесь излитое неотзывно и
  неостановимо, у игрока нет руки на поток — только жёлоба под него.
- **«Щепка»** (предписывать × щепка): там курс предписан щепке и несёт её НЕИЗМЕННОЕ
  поле — курс не руль; здесь жёлоба — руль, который можно крутить между тиками, и
  несёт не поле, а собственный порядок шагов листа.
- **«Очередь»** (зреть × очередь): там дела входят в хвост сами по расписанию и зреют
  сами; здесь вся работа вообще исполняется только сама — ручного труда нет.
- **RoboRally / Human Resource Machine / Opus Magnum / Factorio-подобные** (веб-соседи):
  там программу ПИШЕШЬ ты и носитель — твой (робот, работник, конвейер); порядок
  редактируем, исполнение приостанавливаемо, агентство — в авторстве. Здесь порядок
  задан листом раз и навсегда, лист теряет носителя, исполнение неостановимо, а
  агентство игрока — только геометрия жёлобов во времени.

## Новизна (проверка вебом 2026-11-15, 4 запроса: puzzle game mechanic "runs itself"
  unstoppable automation delegate routine board game; pour program out of programmer
  executes itself game mechanic spell flows automatically; robot executes preprogrammed
  cards unstoppable sequence RoboRally programming puzzle game mechanic; "self-running"
  routine puzzle game route automatic worker steps fixed order stations indie)
Прямого аналога правила «излитый алгоритм теряет носителя и исполняется сам
неостановимо, а игрок подставляет русло шагам» не найдено. Ближайшие соседи и чем
отличаемся: RoboRally — запрограммированный робот исполняет карты неостановимо, но
программу пишешь ТЫ и носитель твой (коллизии планов, а не делегация чужого порядка);
Human Resource Machine / Opus Magnum — авторство программы и пауза/редактирование;
Factorio / Autonauts — автоматизация с полным контролем и паузой; «Robot Command»
(индии, Godot) — платформер «не управляешь персонажем» без геометрии русел и цен
листов; Unstoppable (настолка) — имя совпало, механика — босс-баттля, не delegation.
Жидкостная рифма («лить», «залить на прод») как носитель правила самоисполнения в
жанре не встречена. Слоты библиотеки свободны: ближайшие «Льётся», «Растечься»,
«Черпало», «Щепка», «Очередь» разобраны в Родстве. Слот «неостановимое самоисполнение
чужого порядка + жёлоба вместо руки» пуст.

## Формат прототипа
Один HTML-файл, canvas 960×640, без сборки и зависимостей. Заголовок страницы = вопрос
прототипа. Управление: только мышь (клик по листу, клик по зоне, «Сдать двор», R).
Состояние читается без текста: лента листа с подсветкой текущего шага, стрелки жёлобов,
свет рамок задач, крест хрупкостей, арки проходов, колодец слива, счётчики «тип × N».
HUD одной строкой; финал — автопроверка при сдаче и звёзды. `window.POUR_ALGORITHM`
для headless-ботов.
