# Ведомость — спецификация v1 (после фильтра, GO* 16/16)

## Название
Ведомость (рабочее; эскиз «Сомкнуть список», слот closed-list).

## Пара-источник
смыкаться_VERB × список_NOUN (этап 1 — Σ8, потолок пары 16: №1 = 2, №4 = 2 — мост
«закрытый список», «сомкнуть ряды», №5 = 2 — рукой только клик-скоба, ведомость крутится
сама и больше человека, №8 = 2 — связь: сцепка краёв превращает линию в контур). Стоп-лист
чист. Формула пары: **можно сомкнуть список, но тогда низ начнёт исполняться сразу после
верха — ведомость крутится по кольцу и не кончается, пока не разомкнёшь**.

## Правки фильтра (четыре; №14 и №10 закрывает одна — бюджет сцепок)
1. **Сцепка — ресурс (№14/№15, главная правка).** Эскизный toggle «сомкнуть/разомкнуть»
   бесплатен — тогда доминирует 1-тик осцилляция: сцепка прямо перед полезной строкой,
   один тик, разомкнуть — каждую строку фармят поодиночке, кольцо не нужно, игра
   вырождается. Правка: смыканий на уровень МАЛО (запас скоб), звёзды по числу сцепок
   против par. Теперь короткие дуги безопасны, но дороги; длинный оборот через беду —
   дёшев по сцепкам, дорог по бюджету беды. Две валюты — суть экономики.
2. **Стоп между строками, дожима нет (№10 → определённость; урок «Излитого»).**
   Эскизное «разомкнуть = список кончается» двусмысленно (дожить до края? сразу?).
   Проверка на бумаге: любой вариант «дожима до сцепки» неспасаем — беда всегда
   попадает в дожим (стартом или концом). Правка: размыкание — мгновенный стоп НА ГРАНИ
   тика, между строками; новый обход всегда начинается ЗАНОВО — с первой строки после
   сцепки («заново с нового обхода» из эскиза). Дискретный закон, решаемо на бумаге
   и перебором.
3. **Состав — данные уровня (№9/№13).** Эскизный выбор «КАКИЕ строки в списке» изъят
   из рук: состав и порядок строк неприкосновенны — это закон существительного; рука
   выбирает только зазор сцепки и грань размыкания. Редактор списка = семья Human
   Resource Machine (занята «Излитым») и разрушение инварианта.
4. **Провал конкретизирован (№11/№14).** Эскизное «список крутит вредные строки» →
   строка-беда с МАЛЫМ бюджетом: исполнение сверх бюджета = вещь испорчена = провал
   сразу; плюс тупик: скоб 0, список разомкнут, счёты не закрыты.

## Правило (одно предложение)
Ведомость сомкнута скобой — за последней строкой сразу первая, и она крутится САМА,
исполняя по одной строке за тик и никогда не кончаясь, пока ты не разомкнёшь (клик по
скобе — стоп на грани тика, между строками); разомкнутая ведомость спит, каждое новое
смыкание (клик по зазору) тратит одну из немногих скоб уровня и начинает обход ЗАНОВО,
с первой строки после сцепки, — дела засчитываются в счёты, беды исполняются кольцом
так же неотвратимо, и беда, исполненная сверх своего малого бюджета, — провал, так что
вся игра — где замкнуть кольцо, как долго нести его по кругу и когда успеть разомкнуть
на грани перед бедой.

## Глаголы игрока (только клик; аватара нет)
- **Разомкнуть** (клик по скобе сомкнутого контура): текущая строка доисполняется,
  следующая не начинается — стоп между строками; ведомость спит. Бесплатно, но чтобы
  крутиться дальше — придётся снова смыкать.
- **Сомкнуть** (клик по зазору между строками разомкнутой ведомости): тратит 1 скобу
  из запаса; сцепка встаёт в этот зазор — после строки перед зазором сразу строка
  после него — и обход начинается с первой строки после сцепки. Пока ведомость
  сомкнута, клик по другому зазору отклоняется (скоба одна; сначала разомкни).
- **Заново** (кнопка / R): уровень сбрасывается целиком, детерминировано.
- До первого смыкания время не идёт — думай свободно (думание бесплатно; крутиться —
  нет).

## Токены
- **Строка-дело** — строка кольца с иконкой и счётом-засечками: каждое исполнение
  +1 к её счёту; задачи уровня суть «строка X исполнена ≥ N раз» (прогресс виден
  на строке и в панели задач).
- **Строка-беда** — строка кольца с трещинами (трещин = бюджет): каждое исполнение
  добавляет трещину; бюджет 1–2; исполнение СВЕРХ бюджета = вещь испорчена = провал
  сразу. Последняя допустимая трещина мигает — предупреждение без текста.
- **Скоба / сцепка** — дуга-контур от строки перед сцепкой к строке после неё:
  сомкнута — сплошная дуга с бегущей меткой курсора; разомкнута — пунктир, края
  зазора разъехались. Запас скоб — иконки в HUD; потраченная — гаснет.
- **Курсор** — метка на дуге: какая строка исполнится следующим тиком.
- **Панель задач** — «иконка строки × N» с прогрессом; все закрыты = победа (в любой
  момент, хоть посреди оборота).
- **HUD одной строкой**: «ведомость i/5 · счёт X/Y · скоб: Z (par P)»; кнопка R.

## Инвариант и математика v1 (детерминированная, №9)
- **Кольцо — константа уровня**: состав и циклический порядок строк не меняются
  никогда; сцепка меняет только СТАРТ обхода, не порядок; переставить, дописать,
  вычеркнуть строку нельзя.
- **Сомкнутая ведомость не кончается**: тик = исполнить строку под курсором,
  курсор — к следующей; после строки перед сцепкой — сразу строка после сцепки;
  паузы нет.
- **Счёты монотонны**: исполнения не откатываются; разомкнутая ведомость ничего
  не исполняет.
- **Резолв тика** — чистая функция `(кольцо, сцепка, сомкнута?, счёты, бюджеты,
  скобы)`: действия (клики) резолвятся между тиками; одинаковые последовательности
  кликов дают одинаковые состояния.
- Следствие для солвера: состояние конечное и малое (счёты ≤ 3⁵ × бюджеты ≤ 3³ ×
  скобы ≤ 6 × сцепка ≤ 8 × сомкнута ≤ 2 × курсор ≤ 8) — par доказуемо полным
  перебором на скелете до HTML.

## Двусторонний спрос (№10)
- **Исполнений дел** хочется больше (счёты добываются только исполнениями) и меньше
  (лишний тик — лишняя трещина на пути и удлинение плана).
- **Сцепок** хочется больше (короткие безопасные дуги, гибкость) и меньше (запас
  скоб — жёсткий потолок, звёзды по сцепкам против par).
- **Проходов через беду** хочется и ноль (страшно), и столько, сколько нужно
  (проплатить беду = один длинный обход вместо трёх дуг) — бюджет беды тратимый
  ресурс, как скобы.

## Петли
- **P1 сомкнул → крутится сам**: клик только запускает обход; строки капают без тебя
  (1.2 с/тик); решение живёт в двух кликах — где сцепка и когда разомкнуть.
- **P2 рано/поздно**: разомкнуть на тик позже — беда на пути получила трещину; на тик
  раньше — счёт недобран, придётся новый обход = новая скоба. Грань тика — вся
  драма.
- **P3 две валюты**: скобы против бюджетов бед — длинный обход платит бедами,
  короткие дуги платят скобами; пересцепка между обходами меняет, что пойдёт первым.
- **N1 стоп на грани перед бедой**: последний допустимый проход через беду требует
  разомкнуть за 0 тиков до неё — точность ±1 тик решает провал.
- **Антидоминаторы (№14, боты обязаны подтвердить)**: «не применять» (никогда не
  смыкать) — счёты голы, тупик; «сомкнул и забыл» — беда на втором обороте даёт
  трещину сверх бюджета (L2+ провал); «фарм по-строчно» (сцепка перед каждой делой,
  1 тик, разомкнуть) — скоб не хватает на L2/L4/L5, на L3 впритык без звёзд; «думать
  вечно» — бесплатно только при разомкнутой ведомости, а крутиться без скоб нельзя.

## Цель и проигрыш
- **Цель**: закрыть все счёты уровня (строка × N) — победа мгновенная, посреди любого
  оборота.
- **Звёзды**: 3★ — победа и скоб потрачено ≤ par; 2★ — ≤ par+1; 1★ — победа.
- **Проигрыш**: трещина сверх бюджета беды (вещь испорчена) или тупик (скоб 0,
  разомкнуто, счёты не закрыты) → рестарт уровня (партия ~3–5 минут).

## Вопрос прототипа (один)
Рождает ли вечное кольцо с ограниченными сцепками настоящее ЧТЕНИЕ КОЛЬЦА — где
сцепить, чтобы обход начался с нужной строки, как долго нести его по кругу, платя
бедам их бюджеты, и когда разомкнуть на грани перед бедой, — или игрок смыкает
один раз и забывает / фармит строки поодиночке? Прототип обязан содержать: запас
скоб, беды с бюджетами и миганием последней трещины, par по сцепкам, спам-бота
и осциллятор-бота, обязанных валить L2–L5, — иначе вопрос решён заранее в пользу
«темы».

## Критерии приёмки (боты)
- **Экспорт `window.CLOSED_LIST`** для headless-тестов: `{ CONFIG, LEVELS,
  loadLevel(n), close(gapId), open(), tick(n), state(), log }`. Резолв синхронный
  и детерминированный; действия — между тиками; `tick(n)` исполняет n строк
  (автостоп на победе/провале). `close(gapId)` → `{ok, reason}`: 'no-brackets'
  (скоб 0), 'closed' (уже сомкнуто), 'locked' (уровень закончен). `open()` →
  `{ok, reason}`: 'open' (уже разомкнуто), 'locked'. Отказ не меняет состояние.
  `state()` — сериализуемое `{ level, rows:[{id, kind:'task'|'harm', need, done,
  budget, spent}], closed, joint (gapId|null), cursor, bracketsLeft, bracketsUsed,
  ticks, won, lost, stars }`. Полная информация: счёты, бюджеты, par открыты.
  Приёмка: 5 уровней × 10 партий.
- **Перебор-бот на скелете до HTML** (BFS по состояниям «счёты × бюджеты × скобы ×
  сомкнута × курсор»): par подтверждён перебором 2026-11-22 — **{L1:1, L2:2, L3:2,
  L4:2, L5:3}**, решений «сцепок < par» не существует. Любая правка констант —
  перепрогон до сборки. Обязательно.
- **План-бот** (эталонные решения из «Уровней»): 5/5 побед, сцепок = par → 3★
  везде. Обязательный.
- **Пассив-бот** (никогда не смыкает): не выигрывает нигде; при разомкнутой
  ведомости счёты не меняются. Обязательный (№14 «не применять»).
- **Спам-бот** (сомкнул один раз — никогда не разомкнул): L1 — победа (осознанный
  брешер: кольцо без бед добывает счёты само), L2–L5 — провал трещиной на втором
  обороте. Обязательный (№14 «копить и не останавливаться»).
- **Осциллятор-бот** (фарм по-строчно: сцепка прямо перед каждой делой, 1 тик,
  разомкнуть): L1 — победа без звёзд (осознанный брешер: бед нет, скоб 6), L2–L5 —
  провал (скоб не хватает: L2 4>3, L3 4>3, L4 5>3, L5 7>4). Обязательный
  (№14 «свалить в угол»).
- **Рандом-бот** (случайные легальные клики; 20 000 прогонов, seed 7): L5 — побед
  < 20 %, L3–L4 — < 50 %; замер зафиксировать в сборке (уровень-приём L1/L2 —
  учебные). Обязательный.
- **Инварианты (№9) во всех прогонах любых ботов**: порядок и состав строк
  постоянны; сомкнутая ведомость исполняет ровно одну строку за тик и не кончается;
  счёты и трещины монотонны; сцепка меняет только старт обхода; отказ клика не
  меняет состояние; одинаковые последовательности кликов — одинаковые состояния.
- **№13-щит**: подмена «список → ресурс» ломает кольцо-порядок и вечность (ресурс
  не крутится и не исполняет строки); «сомкнуть → использовать» не тратит скобу,
  не задаёт старт обхода и не даёт вечного оборота — правила меняются.

## Уровни (5, обучение одним намёком; формат: Т-дело / Н-беда (бюджет))
- **L1 «Первое кольцо»** — кольцо [Т-A, Т-B, Т-C]; счёты A×2, B×1, C×1; бед нет;
  скоб 6, par 1. Эталон: сцепка перед A → A,B,C,A (4 тика) → разомкнуть. Учит:
  сомкнул — крутится само; после последней сразу первая; разомкнуть — стоп между
  строками. Провал требует старания (бед нет, скоб 6 — запас на ошибки).
- **L2 «Беда в кольце»** — кольцо [Т-A, Н-X(1), Т-B, Н-Y(1)]; счёты A×2, B×2;
  скоб 3, par 2. Эталон: (1) сцепка перед A: A,X,B,Y,A (5 тиков; стоп перед X) →
  A2, X1, B1, Y1; (2) сцепка перед B: B (1 тик; стоп перед Y) → B2. Форма (b):
  (1) перед B: B,Y,A,X,B; (2) перед A: A. Учит: беда исполняется кольцом как дело;
  проплатить беды один раз дешевле двух дуг; разомкнуть на грани перед бедой.
  Ловушки: поздний стоп — вторая X/Y = провал; фарм по-строчно = 4 скобы > 3.
- **L3 «Пересцепка»** — кольцо [Т-A, Н-X(1), Т-B, Т-C, Н-Y(1), Т-D]; счёты
  A,B,C,D ×2; скоб 3, par 2 (перебор). Эталон: (1) сцепка перед B: B,C,Y,D,A
  (5 тиков; стоп перед X) → B1, C1, Y1, D1, A1 — X ещё не тронута; (2) сцепка
  перед D: D,A,X,B,C (5 тиков; стоп перед Y) → D2, A2, X1, B2, C2. Учит: новый
  обход можно начать с ДРУГОГО зазора — пересцепка меняет, что пойдёт первым, а
  стоп на грани перед бедой сохраняет её бюджет на второй обход. Ловушка: жадный
  первый обход через X (A,X,B,C,Y,D,A) тратит обе беды — остаток добирается
  только узкими дугами, скоб не хватает. Фермa без бед = 4 скобы > 3 — провал.
- **L4 «Две валюты»** — кольцо [Т-A, Т-B, Н-X(2), Т-C, Т-D, Н-Y(1), Т-E]; счёты
  A×3, B×2, C×2, D×2, E×2; скоб 3, par 2. Эталон: (1) перед E: E,A,B,X,C,D,Y,E,A,
  B,X,C,D (13 тиков; стоп перед Y) → E2, A2, B2, X2, C2, D2, Y1; (2) перед A:
  A (1 тик; стоп перед X) → A3. Учит: бюджет беды — ТРАТИМЫЙ ресурс: X терпит два
  прохода, и длинный обход покупает почти всё за одну скобу. Один обход не
  решает: Y(1) не даёт обойти кольцо дважды. Ловушка: жадный второй оборот — Y
  сверх бюджета.
- **L5 «Экзамен»** — кольцо [Т-A, Н-X(2), Т-B, Т-C, Н-Y(1), Т-D, Т-E, Н-Z(1)];
  счёты A×2, B×2, C×3, D×2, E×2; скоб 4, par 3 (перебор). Эталон: (1) сцепка
  перед C: C (1 тик; стоп перед Y); (2) сцепка перед D: D,E,Z,A,X,B,C (7 тиков;
  стоп перед Y) → D1, E1, Z1, A1, X1, B1, C2; (3) сцепка перед A: A,X,B,C,Y,D,E
  (7 тиков; стоп перед Z) → A2, X2, B2, C3, Y1, D2, E2. Требует всё: три обхода
  с точными стопами на гранях перед Y и Z, бюджет X израсходован до конца,
  пересцепки трижды. C×3 не собирается одним обходом: между C и следующим C
  лежит Y(1) — второй проход = провал.

## Стартовые константы (числа для HTML, править при балансировке; эталон — боты)
Тик 1200 мс (вспышка строки — 0.3 с); строк в кольце 3–8; счёты 1–3; бюджеты бед
1–2; скобы на уровень {6, 3, 3, 3, 4}; звёзды: 3 = сцепок ≤ par, 2 = ≤ par+1,
1 = победа. Один экран 960×640: слева — ведомость вертикально (строки 420×64,
зазоры 24 px с иконкой скобы — зоны клика), справа — панель задач (иконка × N +
прогресс), запас скоб иконками, HUD одной строкой: «ведомость i/5 · счёт X/Y ·
скоб: Z (par P)»; кнопка R. Сомкнутый контур — сплошная дуга слева от строк с
бегущей меткой курсора; разомкнутый — пунктир, края зазора разъехались. Трещины
на бедах = исполненные; последняя допустимая мигает. Все константы вверху
прототипа в один объект CONFIG; уровни — данные (ring/kinds/counts/budgets/
brackets/par).

## Риски баланса
- **«Осцилляция доминирует»** — главный страх (убит правкой №1, но следить):
  тест осциллятор-бота (замер: провал на L2–L5, замер par перебором); если фарм
  проходит 3★ где-то — пересобрать счёты/кольцо, не поднимать потолок скоб.
- **«Сомкнул и забыл»** — беды наказывают с L2; если игрок не понимает провала —
  показывать трещины беды крупнее и мигание последней допустимой, не писать текст.
- **«Тик давит»** — до первого смыкания время не идёт; думать — только при
  разомкнутой ведомости (это и есть пауза; пауза при сомкнутой запрещена законом).
  Если не успевают — тик до 1500–2000 мс, не пауза.
- **«Клерковость»** (посчитал и кликнул) — это и есть паззл; давят par и комбинация
  двух валют. Если скучно — кольца длиннее (8–10 строк), не таймер.
- **«Победа мгновенная посреди оборота»** может обесценить размыкание: если игроки
  никогда не размыкаются осознанно — считать звёзды по сумме «скобы + трещины
  бед» (одна валюта из двух), не вводить таймер.

## Что НЕ входит в v1 (осознанно вырезано)
- **Редактирование списка** (переставлять/дописывать/вычеркивать строки) — порядок
  есть закон существительного; редактор = HRM-семья и разрушение №9.
- **Строки-переключатели** (открыть/закрыть люк), строки-таймеры (печь греется
  N тиков), строки-буферы «тишина» — v2; в v1 строка либо дело, либо беда.
- **Несколько ведомостей, вложенные кольца, микрокольцо из 2 строк, враждебные
  ведомости NPC, глобальный таймер / убывающий ресурс** (давление создают беды
  и скобы, не часы) — v2/вне.
- **Тач, сохранения, арт/аудио** — вне v1.

## Родство (проверка фильтра, строгая)
- **«Очередь»** (зреть × очередь): там очередь — НАКОПИТЕЛЬ зреющих дел, пуск —
  руками в цех, закон — давление и выталкивание; исполнение — заказы. Здесь
  список — ИСПОЛНИТЕЛЬ: сам крутит строки по кольцу вечно, рука — только скоба.
  Ядро решений: зрелости под дедлайны vs дуги по кольцу под бюджеты.
- **«Излитое»** (изливать × алгоритм): там лист ОДНОРАЗОВЫЙ — шаги выгорают,
  исполнение кончается, агентство — жёлоба-геометрия. Здесь строки НЕ выгорают:
  кольцо крутится вечно, агентство — сцепка во времени (где замкнуть, когда
  разомкнуть); нет ни головы-прыжка, ни русел.
- **«Лейтмотив»** (перебить × лейтмотив): там петли маршрутов и тактов, сбивка —
  хлопком в паузу, фаза сдвигается; здесь нет сбивки фазы — есть сцепка (старт
  обхода) и размыкание (стоп), беды не сбиваются, а исполняются.
- **«Проникнуться»** (проникаться × этап): там этапы идут по расписанию мира и
  неостановимы; здесь кольцо останавливается рукой и стартует со сцепки —
  расписание принадлежит игроку, закон — только порядок.
- **«Судный день»** (карять × денёк): там неделя крутится сама природой календаря
  и скобы нет; здесь кольцо собирается рукой построчно и крутится строками.
- Веб-соседи: **Loop Hero** — кольцо = местность, всегда замкнуто, игрок кладёт
  плитки, остановки и строк нет; **Human Resource Machine / Loop (Brain Puzzle) /
  Orbit Steps / Opus Magnum** — программу пишешь ТЫ, петли авторские, есть пауза
  и шаг; **Minit / UnLoop / Loophole / Causal Loop** — круговое ВРЕМЯ с эхом, не
  список; **Infinity Loop** — визуальные контуры без исполнения; **трекеры
  привычек (Habitica-класс)** — списки повторяются по дням, но не исполняются,
  не сцепляются и не имеют бюджетов.

## Новизна (проверка вебом 2026-11-22, 4 запроса: closed loop list puzzle game
  mechanic checklist that loops forever; ring execution checklist mechanic game
  tasks repeat in cycle puzzle; Loop Hero hero walks circle automatically loops
  tiles mechanic checklist; puzzle game actions playlist loops repeating sequence
  stop before damage open close loop)

## Формат прототипа
Один HTML-файл, canvas 960×640, без сборки и зависимостей. Заголовок страницы =
вопрос прототипа. Управление: только мышь — клик по скобе (разомкнуть), клик по
зазору (сомкнуть здесь), кнопка R. Состояния читаются без текста: метка курсора
на дуге, вспышка исполняемой строки, засечки счёта на строках, трещины и мигание
бед, сплошная дуга против пунктира, разъехавшиеся края зазора, иконки скоб в HUD.
HUD одной строкой; победа/провал — автопроверка, звёзды по сцепкам. `window.
CLOSED_LIST` для headless-ботов (см. «Критерии приёмки»).
