# Плетение — спецификация v1 (после фильтра, GO* 15/16)

## Название
Плетение (рабочее).

## Пара-источник
сплетаться_VERB × благородие_NOUN (word2vec RusVectores, sim −0.157, cloud_cos −0.18;
архетип «связь» 0.343 — пул pairs_regions_2). Формула пары: **можно сплестись с благородием,
но тогда каждый следующий узел обязан быть знатнее предыдущего**.

## Правка фильтра (три, закрывают №13 + №14 одним изменением цели и №11 переносом жала)
1. **Цель = свойства, не сумма.** Эскиз целился «суммой знатности ≥ X» — под подменой №13
   («благородие → ресурс») правило выживало, а ленивый прыжок «взял короля — сумма набрана»
   вал №14. Заменено заказом-свойствами: ветвь должна ВЛАДЕТЬ конкретными дарами (казна,
   корона, дорога…), и ни одно звание не даёт всех даров сразу. Подмена убивает правило:
   дары качественные и привязаны к званию, король один, «отречение союзников» в ресурс
   не переводится.
2. **Гаситель перенесён с нищего на узурпатора.** При строгой монотонности нищий (ранг 1)
   может стоять только первым — его «ветвь теряет всё» не срабатывало никогда, «обнищал»
   был невозможен. Узурпатор (ранг 4) гасит дары всех узлов, вплетённых РАНЬШЕ него, по
   всему роду — жало бьёт по твоим собственным ветвям (№11). Нищий стал грузовым: ранг 1
   с даром «дорога» (знает тропы).
3. **Действие уточнено до двух кликов: кончик → кандидат.** Эскизное «текущая ветвь
   соединяется» не давало выбора, КУДА вплести; теперь активная ветвь выбирается кликом
   по её кончику (или по дому-корню для новой ветви) — развилка стала механикой, «куда»
   стало решением (№12/№15).

## Правило (одно предложение)
Род плетётся узлами навсегда: клик по кончику ветви делает её активной (клик по дому —
начать новую ветвь), клик по кандидату вплетает его в активную ветвь — кандидат обязан
быть СТРОГО знатнее кончика (лестница званий монотонна, вниз и в сторону сплетаться
нельзя), вплетённое не расплетается никогда, каждый кандидат на карте существует в
единственном экземпляре и исчезает после вплетения, дар узла принадлежит его ветви, а
узурпатор в момент вплетения отрекает все дары узлов ниже знатностью, сплетённых раньше
него по всему роду, — сведи род так, чтобы ветви владели заказанными дарами, пока
кандидаты не кончились.

## Глаголы игрока (только клик; аватара нет)
- **Выбрать кончик** (клик по последнему узлу ветви или по дому): ветвь подсвечивается —
  её кончик станет точкой роста. Клик по дому = новая ветвь от корня (дом сам — «ранг 0»).
- **Вплести** (клик по карточке кандидата на карте родства): кандидат встраивается в
  активную ветвь НАВСЕГДА (анимация нити 0.5 с), исчезает с панели кандидатов; легальные
  кандидаты (строго знатнее активного кончика) подсвечены, нелегальные — приглушены.
  Ховер до клика — превью: если кандидат = узурпатор, все дары, которые отрекутся,
  заштриховываются заранее (решение всегда информировано, случайностей нет).
- **Заново** (кнопка / R): мгновенный рестарт уровня, layout детерминирован.

## Токены
- **Дом (корень)** — низ карты родства; ранг 0, даров не имеет; из него растут все ветви.
- **Ветвь** — цепь дом → n1 → … → nk в порядке вплетения; ранги строго возрастают.
  Активная ветвь одна; её кончик — точка роста.
- **Кандидаты (7 званий v1, каждое в единственном экземпляре на карте уровня)** — карточка:
  портрет, ранг (число корон), дар (иконка), правило:
  - **НИЩИЙ** — ранг 1, дар ДОРОГА (знает тропы).
  - **КУПЕЦ** — ранг 2, дар КАЗНА.
  - **ДЬЯК** — ранг 2, дар ГРАМОТА.
  - **БАРОН** — ранг 3, дар ЗНАМЯ (в v1 — только приманка-ступень).
  - **ГЕРЦОГ** — ранг 4, дар АРМИЯ.
  - **УЗУРПАТОР** — ранг 4, дар АРМИЯ; закон: «прежние союзники отрекаются» — в момент
    вплетения гасятся дары ВСЕХ узлов с рангом < 4, вплетённых раньше него, во ВСЕХ ветвях.
  - **КОРОЛЬ** — ранг 5, дар КОРОНА; после него ветвь заперта (выше никого нет).
- **Заказ уровня** (иконки даров на панели): список требований; требование = «одна ветвь
  владеет набором даров {X, Y}»; разные требования могут закрываться разными ветвями.
  Ветвь владеет даром, если он у её узлов и не отрекён узурпатором.
- **Звёзды** — по числу вплетений против par (см. «Цель»).

## Математика v1 (вся, детерминированная)
- **Инварианты (№9)**: (а) вплетённое не расплетается; (б) ранг каждой ветви строго
  монотонно растёт — порядок сплетения необратимо сжигает ступени: взяв ранг 4, в эту
  ветвь уже не взять 2–3; (в) кандидат уникален — вплетённый в одну ветвь недоступен
  другой. Что бы игрок ни делал, лестница только растёт, и «запас хода» каждой ветви
  тает с каждым кликом.
- **Отречение (№11)**: при вплетении узурпатора все дары узлов ранга < 4, вплетённых
  раньше него (в любых ветвях), гаснут навсегда; его армия и всё, сплетённое ПОСЛЕ
  него, живы. Порядок «узурпатор → слабые» и «слабые → узурпатор» даёт разные роды из
  одних кандидатов.
- **Авто-проверка заказа**: после каждого вплетения; выполнен — уровень сдан (плести
  дальше смысла нет: дары только прибавляются или отрекаются).
- **Тупик = поражение**: легальных вплетений нет (кандидаты кончились или не по рангу),
  заказ не закрыт — рестарт уровня. Необратимость честная: превью и подсветка легальных
  ходов показывают всё до клика.
- **Двусторонний спрос на знатность (№10)**: знатность выше = дары сильнее и корона — но
  каждый высокий узел съедает ступени над собой: герцога хочется взять и хочется
  придержать, чтобы было КУДА расти ради казны и дороги.

## Петли
- **P1 вплёл → ступень сгорела → выбор сузился**: + конструктивная / выбор кандидата и
  ветви (2 клика) / немедленная (лестница пересчиталась, легальные подсветились) /
  короткая / вся ветвь / уровень. Базовое уравнение: «каждый следующий строго знатнее»
  превращает порядок в ресурс, которого меньше с каждым ходом.
- **P2 порядок против гасителя**: + конструктивная / планирование ПОСЛЕДОВАТЕЛЬНОСТИ
  (узурпатор до или после слабых) / отложенная / весь род / уровень. Те же кандидаты в
  другом порядке — разные живые дары.
- **P3 дефицит кандидата (развилка)**: + конструктивная / решение «какой ветви отдашь
  единственного купца» / отложенная / две ветви / уровень. Взявший не той ветвью гасит
  чужое требование навсегда.
- **N1 необратимость**: − destructive / низкое / перманентная / уровень. Прыжок к королю
  запирает ветвь (казна не долетит), узурпатор гасит собранное — оба удара по своему же
  роду (№11), рестарт — единственный откат.
- **N2 впритык**: − напряжённая / высокое / уровень. Звёзды считают вплетения: каждая
  лишняя ступень лесенки — минус звезда.

## Цель и проигрыш
- **Цель уровня**: выполнить заказ (все требования) — авто-сдача при выполнении.
- **Звёзды по узлам**: 3★ — вплетений ровно par (минимум, посчитан полным перебором);
  2★ — par+1; 1★ — победа. Пар-таблица ниже, подтверждена перебором.
- **Проигрыш**: тупик (нет легальных ходов, заказ не закрыт) → мгновенный рестарт.
  Партия 5 уровней ≈ 5 минут.

## Вопрос прототипа (один)
Рождает ли строго монотонная лестница знатности с необратимыми узлами-дарами настоящее
планирование ПОРЯДКА — кого вплетать раньше гасителя, какой ветви отдать единственного
кандидата, когда лезть наверх, — или игрок жмёт самых знатных подряд / плетёт всех
слабых подряд? Прототип обязан содержать: узурпатора-гасителя (иначе порядок даром),
дефицит кандидатов между ветвями (иначе развилка даром), короля с запертой ветвью
(иначе прыжок выгоден) и par-звёзды — иначе вопрос решён заранее в пользу «темы».

## Критерии приёмки (боты)
- **Экспорт `window.WEAVE`** для headless-тестов: `{ CONFIG, LEVELS, select(tipId),
  weave(candidateId), restart(), state() }`; `tipId` — индекс ветви или `'root'` (новая
  ветвь). `state()` отдаёт сериализуемый объект `{ level, candidates:[{id, name, rank,
  gift, taken}], chains:[{nodes:[{id, rank, gift, alive}]}], active, order:{reqs:[[gift]]},
  weaves, par, won, lost, stars, giftsByChain:[[gift]] }`; `select/weave` возвращают
  `{ok, reason}`. Все решения ботов — через этот API, без пикселей.
- **План-бот** (par-линии уровней, ниже) — **5/5 уровней, 3★ везде**.
- **Рандом-бот** (равновероятно любое легальное (ветвь × кандидат)) — **<50% побед на
  каждом уровне** (≥20000 headless партий). Бумажный перебор: L1 20.4%, L2 18.7%,
  L3 37.3%, L4 3.8%, L5 2.4% — прототип обязан подтвердить замером.
- **Бот «жадный: самый знатный»** (анти-прыжок) — **тупик на L1, L2, L4, L5**; на L3
  побеждает, но 4 вплетения при par 3 = 2★ (жёсткий критерий №14: прыжок никогда не
  даёт 3★).
- **Бот «слабый: самый незнатный»** (анти-«плети всех подряд») — **тупик на L3, L4, L5**
  (на L3 узурпатор, вплетённый последним, гасит казну и грамоту); L1–L2 выигрывает — там
  лесенка и есть урок.
- **Бот «первый-клик»** (левее на карте) — **тупик на L4, L5**; L1 3★, L2 2★, L3 2★.
- Политика цепей всех ботов: продолжить активную ветвь, если кандидат легален, иначе
  новая ветвь от дома; tie-break — левее на карте.

## Уровни (5, обучение одним намёком; par и проценты проверены полным перебором)
Карты записаны в порядке панели кандидатов (слева направо).

- **L1 «Первая сплетня»** — карта: нищий, купец, герцог. Заказ: {ДОРОГА ∧ КАЗНА} одной
  ветвью. Учит: клик = вплести навсегда; строго знатнее — нищий обязан встать раньше
  купца (обратный порядок нелегален). par=2: **нищий → купец** одной ветвью. Жадный
  (герцог первым) — тупик: в ветвь с герцогом купец не влетит. Случайный 20.4%.
- **L2 «Прыжок к королю»** — карта: купец, герцог, король. Заказ: {КОРОНА ∧ КАЗНА} одной
  ветвью. Учит: самое знатное первым запирает ветвь — король первым = казни некуда
  встать. par=2: **купец → король**. 2★-линия: купец → герцог → король (герцог —
  лишняя съеденная ступень). Жадный — тупик. Случайный 18.7%.
- **L3 «Отречение»** — карта: узурпатор, дьяк, барон, купец. Заказ: {АРМИЯ} ∧ {ГРАМОТА} ∧
  {КАЗНА} (требования могут сидеть в разных ветвях). Учит: узурпатор гасит всё,
  сплетённое РАНЬШЕ него, по всему роду — плети его ПЕРВЫМ. par=3: **узурпатор → дьяк →
  купец** (три ветви от дома; слабые после гасителя живы). Узурпатор последним = казна и
  грамота отрекаются = тупик (так умирает бот «слабый»; «жадный» и «первый-клик»
  побеждают за 4 вплетения = 2★, не 3★). Барон — приманка-ступень. Случайный 37.3% (самый
  щедрый — порядок здесь прощает многое, кроме гасителя в конце).
- **L4 «Две ветви»** — карта: нищий, купец, дьяк, герцог. Заказ: {КАЗНА ∧ АРМИЯ} одной
  ветвью ∧ {ДОРОГА ∧ ГРАМОТА} одной ветвью. Учит: кандидаты дефицитны между ветвями —
  купец нужен ветви с герцогом, нищий — ветви с дьяком; отдай не той ветви — чужое
  требование мертво. par=4: **нищий → дьяк ∧ купец → герцог** (две ветви; 6 победных
  линий — все одно чередование, форма единственная). Любой бот-ленивец — тупик.
  Случайный 3.8%.
- **L5 «Род»** — карта: нищий, купец, барон, узурпатор, король. Заказ: {КОРОНА ∧ КАЗНА}
  одной ветвью ∧ {АРМИЯ} ∧ {ДОРОГА}. Экзамен: узурпатор ДО купца (иначе казна отрекается
  — удар по своему роду), король последним в своей ветви (раньше — заперта), нищий —
  отдельной ветвью. par=4: **узурпатор → нищий → купец → король** (ветви: [узурпатор],
  [нищий], [купец → король]); 2★-линия съедает барона пятой ступенью (32 победные
  линии). Жадный, слабый, первый-клик — все в тупике. Случайный 2.4%.

Навыки по уровням: «клик навсегда, строго знатнее» — L1; «прыжок запирает ветвь» — L2;
«гаситель раньше слабых» — L3, L5; «дефицит кандидата между ветвями» — L4, L5;
«король — конец ветви» — L2, L5.

## Стартовые константы (числа для HTML, править при балансировке)
Один экран 960×640: слева карта родства 600 px — дом-корень внизу по центру (96×96),
ветви растут вверх цепочками узлов 72×72 (шаг 110 px по вертикали, ветви расходятся
веером ±40°); активная ветвь — яркая нить, неактивные — приглушены; отрекённые дары —
штриховка узла. Справа панель кандидатов 320 px: карточки 128×128 (портрет, ранг = число
корон, иконка дара, узурпатор — знак отречения); легальные для активного кончика
подсвечены, нелегальные приглушены; под панелью блок заказа (иконки даров по требованиям)
и счёт «вплетений / par» с пером-иконкой. Кнопки «Заново» и R. Вплетение — анимация нити
0.5 с; отречение — 0.4 с штриховки всех гасимых даров (и в превью по ховеру). Все
константы вверху файла прототипа в один объект CONFIG; уровни — данные
(map/order/par/positions). Победа — авто-проверка после вплетения; тупик — рестарт.

## Риски баланса
- **«Всегда самых знатных» (прыжок)** — главный страх эскиза. Проверено перебором:
  тупик на L1, L2, L4, L5 и 1★ на L3. Если какая-то линия вдруг проходит — резать
  карты (убирать дублирующий дар), не вводить случайность.
- **«Лесенка снизу всегда» (слабый бот)** — на L1/L2 совпадает с уроком (так задумано),
  с L3 умирает об отречение и дефицит. Против полной победы слабого бота следить, чтобы
  в каждой карте после L2 был либо гаситель, либо требование «высокое + низкое в одной
  ветви».
- **Превью убирает напряжение** — по дизайну это пазл полного знания (как «Устой» и
  «Познакомить»): вопрос не в риске, а в порядке и распределении. Если скучно —
  ужесточать par (звёзды), не прятать отречение.
- **Читаемость знатности** — ранг виден числом корон на карточке и узле; если игрок
  путается, почему кандидат приглушён, подсветить кончик активной ветви и показать
  «строго выше» стрелкой в превью, не текстом-правилом.
- **Отречение не замечают** — ховер-превью обязано штриховать будущие потери; если
  тестеры всё равно гибнут внезапно, добавить после первого отречения одноэкранную
  паузу с обрывом нитей (не подсказку).
- **Случайность нулевая**: любые правки карт/рангов/даров обязаны перепроверяться
  полным перебором (скрипт-эталон остаётся в истории: par, число победных линий,
  проценты случайного бота) и повторным замером ботов.

## Что НЕ входит в v1 (осознанно вырезано)
- **Несколько кандидатов одного звания на карте** и дар «знамя» в заказах (барон —
  только приманка-ступень) — кандидат v2.
- **Второй гаситель** («вдова: ветвь выше мертвеца теряет корону») и правило у нищего —
  при строгой монотонности ранг-1 гаситель мёртв; гасители только ранга 4+.
- **Переплетение/развод ветвей за цену**, grafting ветви в середину другой ветви,
  кандидат «шут» (любой ранг) — v2.
- **Сезон/таймер/поток кандидатов** (род живёт в реальном времени) — v2; v1 —
  детерминированный пазл полного знания.
- **Счёт против других родов, сохранения, тач, арт/аудио** — v2.

## Новизна (проверка вебом 2026-11-15, 3 запроса)
Прямого аналога формулы «сплетаешься с благородием — каждый следующий узел строго
знатнее, узел = постоянный модификатор всей ветви выше, кандидаты уникальны» не найдено.
Ближайшие соседи и чем отличаемся:
- **Ancestree** (Eric Lang, настолка) и **Family Tree!** — построение родословного
  дерева: тайлы/силуэты соединяются по родству ради очков или по подсказкам; нет
  монотонного закона знатности, нет правил-модификаторов узла, кандидаты не уникальны
  и не конкурируют между ветвями.
- **Dynasty Rule / Noble** (династийные симуляторы) — браки, наследники, менеджмент
  рода; прогрессия без строгого закона «каждый следующий знатнее» и без пазл-заказов
  на дары.
- **Лестничные карточные игры** (President-ряд «положи выше или забери сброс», кооп
  **The Game** с восходящими стопками) — строго возрастающая цепь есть, но это плоская
  цепь чисел: без даров, гасителя, дерева и выбора ветви.
- **Перманентные модификаторы забега** (Slay the Spire — реликвии) — собираются
  наградами и не образуют обязывающей лестницы порядка; «больше» не запрещает «меньше»
  следующим шагом.
Занятые слоты проекта: «Устой» — выбор правила на этаж, но вес несётся ВНИЗ по
физической цепи, порядка-лестницы нет и переставлять можно состав; тут — лестница
знатности ВВЕРХ, вес не несётся вовсе, запрещён сам порядок (строго знатнее, свапа и
спуска нет). «Знаменовать» — закон от гостя, но законы переставляются по кругу и активен
один; тут законы навсегда и лестницей, ветвей много. «Обмен тенями» — парный свап;
тут свапа нет по построению. «Познакомить» — навсегда-знакомство, но симметричное
усреднение с сохранением суммы; тут асимметричный строгий рост без инварианта суммы.
«Заслуга в расход» — подъём за валюту-медали; тут валюты нет — сам порядок сплетения
расходуется. Комбинация «строго монотонная лестница ∧ узел-модификатор ветви ∧
уникальные кандидаты ∧ гаситель по всему роду» новизну держит.

## Формат прототипа
Один HTML-файл, canvas 960×640, без сборки и зависимостей. Управление: только мышь
(клик по кончику/дому, клик по карточке кандидата, «Заново»). Состояние мира читается
без текста: ранг — короны, дары — иконки, легальность — подсветка, отречение — штриховка
(в живом роде и в превью), заказ — иконки требований, пар — перо. Заголовок страницы =
вопрос прототипа. `window.WEAVE` — экспорт для ботов (см. «Критерии приёмки»).
