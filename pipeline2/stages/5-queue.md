# Этап 5. Очередь

**Назначение.** Держать короткий список механик, на которые тратится дорогая работа — спека, ассеты,
прототип, плейтест. Всё остальное остаётся библиотекой.

**Кто.** Инструмент `tools/build_queue`; запускает ведущий после каждого изменения любого `verdict.json`.

## Вход
Все `mechanics/*/verdict.json` второй версии (в них есть поле `pipeline: 2`).

## Правила
Числа — в `config.yaml`, раздел `queue`.

1. **Кто претендует.** Механики со статусами `checked`, `queued`, `library`, `displaced` и закреплённые
   (`pinned_statuses`: уже есть спека, ассеты или прототип).
2. **Закреплённые остаются.** Механику, по которой начата дорогая работа, из очереди не вытесняют.
3. **Остальные места** занимают лучшие по сырому баллу. При равенстве — `tie_break`: сначала с меньшим
   штрафом за цену, потом более ранняя.
4. **Размер** — `size` мест вместе с закреплёнными.
5. **Статусы после пересчёта:** попала — `queued`; была в очереди и выпала — `displaced`; не попала ни разу —
   `library`. Смена статуса записывается в историю `verdict.json` с баллом вытеснившей.
6. **Порядок сборки** внутри очереди — `build_order`: сначала с меньшей ценой ответа (`S`, потом `M`, потом
   `L`), при равной — с большим баллом.
7. **Контрольный прототип.** Каждый `control_every`-й прототип собирается не из верха очереди, а по механике
   с наименьшим баллом среди `library`. Она получает пометку `"control": true`. Так проверяется сам балл:
   если контрольные играются не хуже лучших, балл ничего не предсказывает.
8. **Стоп поиска.** Если в очереди `stop_sampling_at` или больше механик без исхода плейтеста, этап 0 не
   запускается.

## Что должно получиться
- `state/queue.json` — очередь данными (формат — в `artifacts.md`).
- `state/queue.md` — она же таблицей для человека: место, механика, балл по слагаемым, цена ответа, статус,
  что делать следующим; ниже — три последних вытесненных и причина.

## Что запрещено
- Править очередь руками. Изменить её можно только через `verdict.json` и пересчёт.
- Поднимать балл правками ради места в очереди: очередь строится по сырому баллу.
- Исключение одно: пользователь может поставить механику в очередь или убрать из неё словами. Тогда в
  `verdict.json` пишется `"user_override"` с датой и его формулировкой, и инструмент это учитывает.

## Источник правил
Список сужают до немногих идей и работают с ними (Fullerton, гл. 6, p.228). Порядок по цене ответа — правило
первой версии (`AGENTS.md`, «Ранжирование и контроль»); контрольный прототип — оттуда же. Размер очереди —
оценка автора пайплайна.
